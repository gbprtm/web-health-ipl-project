## Kriteria Terima

1. Setiap FR-01 sampai FR-14 memiliki minimal satu endpoint tertulis.
2. Setiap endpoint mencantumkan method, path, role, request, response, dan galat.
3. Respons sukses mengikuti helper A07 dengan bentuk `{ data }`.
4. Respons galat mengikuti helper A07 dengan bentuk `{ error: { code, message, fields? } }`.
5. Nama field dan batas akses pasien/admin disepakati sebelum implementasi backend dan frontend.

## Hasil

`docs/api-contract.md` memuat:

- Konvensi base path `/api`, ID UUID, tanggal WIB, timestamp, session cookie, dan validasi server-side.
- Bentuk respons sukses dan galat yang sama dengan `src/lib/http.ts`.
- Kode HTTP dan kode galat domain.
- Endpoint untuk FR-01 sampai FR-14.
- Role yang diizinkan pada setiap endpoint.
- Contoh request dan response.
- Aturan pembatasan resource milik pasien sendiri.
- Aturan penolakan pasien pada endpoint admin.
- Aturan audit log dan operasi yang wajib menghasilkan audit.
- Traceability FR ke endpoint.
- Daftar keputusan yang masih terbuka dan tidak boleh dikunci diam-diam di handler.

## Verifikasi dokumen

- FR-01 sampai FR-14 tercantum pada bagian endpoint.
- Bentuk sukses `{ data }` tercantum pada bagian 2.1.
- Bentuk galat `{ error: { code, message, fields? } }` tercantum pada bagian 2.2.
- Kontrak membedakan role `pasien`, `admin`, dan tidak menyediakan login dokter.

A15 adalah tugas dokumentasi. Tidak ada endpoint yang dibuat atau diuji pada
sesi ini. Kontrak API menjadi dasar implementasi backend dan frontend berikutnya.
